# mirae_asset_2026 — 공시 Agent

제10회 2026 미래에셋증권 AI Festival 참가 프로젝트. 과제는 **공시 Agent(Disclosure Analyst)** —
DART 공시 데이터를 근거로 자연어 질의에 검색·비교·계산·근거기반 답변을 하는 AI Agent.

## 대회 핵심 규정

- **LLM은 HyperCLOVA X만 사용 가능.** 다른 LLM 사용 시 평가 제외.
- 제공 코퍼스 외 데이터(뉴스·리포트·위키 등) 사용 불가, OpenDART 등 외부 API 실시간 호출 불가.
- 근거 없는 미래예측·투자의견 생성 금지. 확인 불가 시 "확인할 수 없음" 명시 필수.
- 모든 답변에 근거 공시 표시 필수.
- 예선 제출 **마감 09.06 23:59(KST)** — 소스코드+환경정보 / 기술제안서 / 평가용 API 서버.
  마감 후 결과물 변경 목적의 커밋·배포는 실격. (장애로 인한 단순 재기동은 실격 아님)

주최측 Q&A에서 확인된 운영 조건: 질의는 **순차(sequential)** 호출, 응답 타임아웃 **300초**,
호출 실패 시 주최측 재시도 **2회**, Dockerfile은 필수가 아니고 `requirements.txt` 등
재현 가능한 환경 정보면 됨, 전처리 산출물도 제출 대상(대용량은 스토리지 링크 가능),
형태소 분석기·규칙 기반 NLP는 사용 제한 없음.

## 빠른 시작

```bash
pip install -r requirements.txt
streamlit run app.py            # 코퍼스도 API 키도 필요 없다
```

저장소에 **적재 완료된 DB의 압축본**(`index/disclosure.db.gz`, 16MB)이 들어 있어서,
5.15GB 코퍼스가 없어도 데모가 바로 돈다. 첫 실행 때 자동으로 풀린다.

코퍼스를 갖고 있고 직접 다시 만들려면:

```bash
python -m lib.ingest            # 전처리, 8~10분
python -m lib.store pack        # 배포본 갱신 (76MB → 16MB)
```

원본 DB(76MB)는 git에 두지 않는다. 원장에서 결정론적으로 재생성되는 파생물이라
스크립트로 언제든 다시 만들 수 있고, 그게 이 설계의 요점이기도 하다. 압축본만
얹어두는 이유는 팀원과 배포 환경이 코퍼스 없이도 돌려볼 수 있게 하기 위해서다.

## 저장소 구조

```
lib/
├── parser.py     DART XML 보정 파서 + 거래소공시 HTML 폼 파서 + 포맷 라우팅
├── entity.py     법인명·상장명·제출인 별칭 해석
├── store.py      SQLite 스키마 (docs / claims / edges / contracts / chunks)
├── ingest.py     적재 파이프라인 (normalize → extract), 단계별 재실행 가능

└── agent.py      질의 계획기 — 슬롯 번역 + 규칙 기반 툴 선택 + 근거 검증

eda/
├── generate_eda.py  1차 EDA (집계 검증)
├── audit_v2.py      정밀 감사 — 필드·그룹 레벨 함정 전수 조사
└── report.html      1차 EDA 시각화 리포트
eval/
├── eval_set.json     1차 검증셋 13문항

```

`data/`와 `과제소개자료/`는 git에 올리지 않는다(Google Drive 별도 보관).

## 설계

### 두 축, 여섯 유형, 세 테이블

데이터를 두 축으로 가른다. **데이터 성격**(완전정형 / 서사형 / 얕은 관계)과
**시간 의미론**(상태 / 사건)이다. 두 번째 축은 우리가 붙인 게 아니라 데이터에 이미
있었다 — `base_year`/`base_month`가 정기공시 1,054건에는 100% 있고 나머지 3,150건에는
100% 없다. DART 제도 자체의 정기공시(주기적 상태 보고)와 수시공시(사건 발생 보고)
구분과 일치한다.

|  | 상태 — 기간 귀속, as-of 조회 | 사건 — 시점 발생, 순서·인과 |
|---|---|---|
| **완전정형** | `claims.valid_year` · 재무 팩트 | `claims.event_dt` · 계약금액·체결일 |
| **서사형** | `chunks`(periodic) · 사업의 내용 | `chunks`(exchange·major) · 계약 내용 |
| **얕은 관계** | `edges`(ownership) · 지분 현황 | `edges`(correction) · 정정 체인 |

6유형이 6개 테이블은 아니다. **데이터 성격 축은 테이블을 가르고, 상태/사건 축은
테이블이 아니라 컬럼과 조회 규칙을 가른다.** 물리 저장소는 SQLite 파일 하나뿐이다.

### 정정을 특수 처리하지 않는다

`claims`와 `edges`는 append-only 원장이다. 정정본이 주장하는 값을 그 문서의 접수일로
쌓아두고, 조회 시점에 주장 시점이 가장 늦은 것을 채택한다. 그래서 **원본을 찾아
연결하는 단계가 아예 없고**, 원본이 코퍼스 밖인 정정 280건에 대해서도 최신 상태는
정확하게 나온다. "완벽한 시트를 만들 것인가, 갱신 가능한 구조로 갈 것인가"는
트레이드오프가 아니었다 — 시트는 값을 저장하지만 "언제 기준으로 참인 값인가"를
버리기 때문에, 정정률 24%인 이 데이터에서는 오히려 부정확하다.

### LLM은 툴을 고르지 않는다

질문을 슬롯(기업·기간·계정·의도)으로 번역하는 데까지가 언어 처리이고, 어느 툴을
부를지는 규칙이 결정론적으로 정한다. 정확도 때문이기도 하고 호출 한도 때문이기도
하다 — CLOVA Studio는 분당 요청·토큰 상한이 있고 타 팀이 429를 실측했다. 라우팅에
LLM 호출이 0이면 한 질의당 호출을 답변 생성 1회로 묶을 수 있다.

가드레일 셋을 건다. **엔티티가 안 풀리면 즉시 중단**하고(조용한 0건이 "자료 없음"으로
위장하는 것을 막는다), **모든 툴이 3값을 반환**하며(확인됨 / 0건으로 확인 / 범위 밖),
**답변 생성 후 근거를 검증**한다(답변의 수치가 조회 결과에 실재하는지 로컬에서 대조).

## EDA v2 — 정밀 감사에서 나온 것

`python eda/audit_v2.py` 로 재현한다. 1차 EDA가 "집계가 맞는가"를 봤다면, v2는
"집계는 맞는데 필드·그룹 레벨에서 갈라지는 곳이 어디인가"를 봤다.

1. **표준 XML 파서로 원문이 안 열린다.** 통과율이 periodic 0/70, major 409/598,
   holding 815/1,083. 원인은 원문의 스키마 위반 세 가지(이스케이프 안 된 `&`,
   육안용 홑화살괄호, 속성값 내 따옴표). `recover=True`만 쓰면 파싱은 되지만
   `<연결현금흐름표>` 같은 **표 라벨을 통째로 버려** periodic 43%에서 손실이 났다.
   보정 후 recover로 넘기면 파싱 100% + 라벨 소실 0건이 된다.
2. **거래소공시 정정본의 원본 44%가 코퍼스 밖이다.** 정정 631건 중 원본 매칭은
   51.3%뿐이고 280건은 원본 제출일이 2008~2022년이다. 이 구간은 "확인할 수 없음"이
   정답이며, 정정 체인 테이블은 이를 `dangling_out_of_corpus` 상태로 명시한다.
3. **질의어로 회사를 못 찾는 경우가 있다.** `corp_name`(법인명)과 `listed_name`(상장명)이
   다른 기업이 6개사, 문서 327건. 현대차/현대자동차, KT/케이티, 엔씨소프트/NC,
   LIG넥스원/LIG디펜스앤에어로스페이스 등.
4. **XML이 없는 정기공시 3건.** PDF와 뷰어 HTML만 있다(KB금융·한화오션·한화에어로스페이스).
   본문 경로를 이름으로 가정하지 않고 디렉토리를 확인해 `unsupported_format`으로 기록한다.
5. 그 밖에 major 598건 전건 `doc_subtype` 결측(`report_nm` 괄호로 597건 복구),
   문서 0건인 (기업, 유형) 조합 33개, 지분공시 제출인이 발행회사와 전건 불일치,
   `[첨부추가]`본 6건이 `is_correction=false`로 수집된 점.

전체 리포트: [공시 코퍼스 정밀 감사](https://claude.ai/code/artifact/709792ef-8dce-4dfc-89d3-7305d8bf99fe)

## 모의고사 v2 (`eval/mock_exam_v2.json`)

정확도를 재는 시험이 아니라 **어디서 깨지는지를 재는 시험**이다. 감사에서 나온 함정
15종에 문항을 하나씩 매핑해 격리 테스트한다. 각 문항에 `distractor`(순진한 시스템이
낼 법한 오답)와 `auto_fail`(치명적 오류 조건)이 붙어 있어, 틀리면 어느 설계 결함인지
바로 특정된다.

문항의 약 1/3이 **"확인할 수 없음"이 정답**이다(평가지표 '정보한계대응'). 다만 과잉
거절도 오답으로 잡는다 — 삼성전자의 2021년 매출액은 2021년 보고서가 없어도 2023년
사업보고서 비교표에 있으므로 답해야 한다.

### 알려진 한계

- 재무 팩트 커버리지가 70개사 중 매출액 56 · 영업이익 58 · 자산총계 65다. 요약재무정보
  표 레이아웃이 기업마다 더 갈리는 경우가 남아 있다. 미수집 기업은 값을 지어내지 않고
  `known_empty`로 응답한다.
- 계약 클러스터는 정정공시가 명시적으로 지목한 원본으로만 묶는다. 해지공시는 아직
  원계약과 자동 연결되지 않는다.
- 벡터 검색은 아직 붙이지 않았다. 어휘 검색(BM25)만으로 동작하며, 임베딩은 규정 확인
  후 CLOVA Studio 것으로 붙일 예정이다.
