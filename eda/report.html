제10회 2026 미래에셋증권 AI Festival "공시 Agent" 과제 — DART 공시 코퍼스(data/3.공시/corpus) 전수 분석. 기업 마스터, 문서 메타데이터, 원문 4,616개 XML/HTML 파일의 구조와 분포를 확인했다. 2026-08-15 기준.

1. 기업 유니버스

universe.csv · 70행 × 17열

섹터별 대표기업을 시가총액·산업대표성 기준으로 수기 선정한 70개사(KOSPI 61 / KOSDAQ 9). fiscal_month는 전 기업 12월로 상수(분산 없음).

업종(대분류)별 기업 수

8개 업종 · 산업재가 23개사로 최다

상장연도 분포

최근 5년 이내 상장 8개사 — 정기공시 건수가 구조적으로 적음

시가총액 상위 15개사

단위: 억원 · 로그 스케일(삼성전자 1,458만억 ↔ 최소 7,439억, 약 2,000배 격차)

2. 문서 메타데이터

manifest.jsonl · 4,204행 × 19열

4개 원문 유형(doc_group)의 색상은 이후 모든 차트에서 동일하게 유지 — 정기공시 · 주요사항보고서 · 거래소공시 · 지분공시.

원문 유형별 문서 수

거래소공시가 1,469건으로 최다, 주요사항보고서가 598건으로 최소

세부 유형(doc_subtype)별 문서 수

단일판매·공급계약체결이 1,106건으로 전체의 26%

월별 제출 건수 추이 (2023-01 ~ 2026-06)

3·5·8·11월에 뚜렷한 스파이크 — 정기공시 제출기한(결산후 45~90일)과 일치하는 계절성

원문 유형별 정정공시 비율

거래소공시 43% vs 지분공시 3.8% — 유형별 편차가 매우 큼

정정공시 비율 상위 10개사

건설·EPC 계열이 상위권 — 수주 공시 정정이 잦음

3. 원문 구조 (raw/)

XML 4,616개 · 5.15GB

정기공시·주요사항보고서·지분공시는 DART 고유 DOCUMENT XML 스키마, 거래소공시는 확장자만 .xml이고 실제 내용은 HTML 폼 — 최소 2종의 파서가 필요하다.

원문 유형별 문서 크기(중앙값)

로그 스케일 · 정기공시 3.8MB vs 거래소공시 9.8KB, 약 400배 격차

원문 유형별 <TABLE> 태그 밀도

로그 스케일(샘플 20건 평균) · 거래소공시는 HTML 소문자 <table>이라 0으로 집계

4. 핵심 발견

무결성 확인

universe.csv의 n_periodic/n_major/n_exchange/n_holding 선언 건수와 manifest.jsonl 실제 집계가 70개사 전원 완전히 일치. 데이터 자체의 정합성 문제는 발견되지 않음.

스키마 설계 필수 반영

지분공시(holding) 1,083건 전건에서 flr_nm(제출인)이 corp_name(발행회사)과 다름 — 실제 제출 주체는 대량보유자(예: 국민연금, BlackRock, 계열사)다. "누가 얼마나 보유했는가" 질의에는 corp_name이 아니라 flr_nm이 핵심 엔터티.

파서 분리 필요

거래소공시(exchange)만 유일하게 HTML 폼 구조(span 기반 key-value). 나머지 3종(DART DOCUMENT XML)과 최소 2개의 파서 경로가 필요하다.

구조 재사용 가능

정기공시는 반도체·은행·보험·증권 등 업종과 무관하게 I~XII 표준 목차가 100% 동일(4개 업종 샘플 비교 확인). 섹션 기반 파서 하나로 70개사 전체 정기공시를 커버할 수 있다.

정정 이력 추적 우선순위

거래소공시 정정비율 43%, 주요사항보고서 28.9% — "최신 계약 조건이 뭐야?" 유형 질의는 원본과 정정본을 시간순으로 연결하는 로직 없이는 오답 위험이 크다.
